# 8교시 실습·형성평가 워크북

README는 코드를 만들기 위한 이론서이며, 이 문서는 교시별 수행 순서와 평가 기준이다. 각 시간표의 합은 50분이다. 교시 사이 휴식은 포함하지 않는다. 예상 오류와 보충 활동은 수업 설계이며 실제 수강생에게 관찰된 결과가 아니다.

실습 작업 위치는 항상 `LangChain_8Sessions` 최상위 폴더다. `lessons/`의 각 교시 예제는 다른 교시가 없어도 해당 명령으로 시작할 수 있다. 1~6교시 확장 코드는 필요하면 `submission/`에 별도 파일로 작성한다. 이 폴더를 직접 만들고 빈 `__init__.py`를 넣으면 `python -m submission.practice02`처럼 실행할 수 있다. 파일을 바꾸기 전 복사본을 남기며, 복구가 필요하면 원본 ZIP의 해당 파일을 다시 꺼내 비교한다. 이미 완성한 코드를 지우고 다시 채우는 방식으로 진행하지 않는다.

공통 AI 규칙은 **연습의 오류 해설·대안 비평에는 허용, 독립 확인에는 금지**다. API를 호출하는 것은 과제 수행 기능이고, AI 코딩 도구로 정답을 얻는 것은 평가 지원 도구다. 둘은 다르다. 독립 과제에서 미리 작성한 모델 팩토리를 사용하는 것은 허용한다. 해설을 확인한 과제는 ‘해설 참고’로 표시하고 다른 입력·새 조건으로 독립 수행을 재확인한다.

힌트는 ①질문 → ②개념 → ③의사코드 → ④부분 코드 → ⑤해설 순으로 제공한다. 설명과 새로운 값 수정에 성공하면 다음 과제에서 한 단계 줄인다. 3분 이상 아무 진전이 없으면 한 단계를 복원한다. 해설 이후에는 같은 문제 반복을 독립 증거로 사용하지 않는다.

## 1교시 — 환경을 준비하고 첫 호출을 구분한다

**문제 상황:** Python은 실행되지만 패키지가 다른 환경에 설치되어 안내문 프로그램이 시작하지 않는다. 환경을 맞춘 뒤 템플릿 생성과 모델 호출을 구분해야 한다.

### 목표와 성공 증거

| 목표 | 활동 | 제출 증거 | 통과 기준 |
| --- | --- | --- | --- |
| 가상환경과 패키지 경로를 확인한다 | Python 경로·버전 확인 | 버전/경로 기록 | 실행 Python이 프로젝트 venv에 연결됨 |
| 템플릿 실행과 모델 실행을 구분한다 | 두 invoke의 출력 관찰 | 타입 2개·호출 수 설명 | ChatPromptValue와 AIMessage, 실제 호출 1회 구별 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | 선수 진단 3문항, 오늘 만들 결과 확인 |
| 5~13분 | README 1장: 메시지·패키지·invoke 설명 |
| 13~35분 | 환경 생성·설치·API 설정 또는 모의 실행, 복구 대기 포함 |
| 35~45분 | 질문 값을 바꾸어 재실행하고 타입·비용 발생 위치 설명 |
| 45~50분 | 독립 형성평가 |

**선수 진단:** ①`{'x':1}['y']`의 결과는? ②`return`이 없는 함수 호출 결과는? ③가상환경을 나누는 이유는? 설계상 0~1문항 정답이면 dict/함수 보충 5분을 실습 앞부분에 배정한다. 2문항이면 기본 실습, 3문항이면 확장 설명까지 진행한다. 분기 기준은 수업 운영용이며 학생의 고정 수준을 판정하지 않는다.

### 수행 순서

1. README 환경 안내에 따라 venv를 만들고 잠금 파일을 설치한다. `python -m pip check`에서 의존성 충돌이 없는지 확인한다.
2. `python -m lessons.s01_environment.main --mock` 실행 전에 출력 타입을 예측해 적는다.
3. 실행 결과에서 `ChatPromptValue`, `AIMessage`, `[MOCK: 품질평가 제외]`를 찾는다. 패키지 버전 숫자도 남긴다.
4. 파일의 `question` 값을 ‘LCEL을 한 문장으로 설명해 주세요’로 바꾼다. `--mock`에서는 응답 문장이 바뀌지 않는 이유를 말한다.
5. 제공 키가 준비되어 있으면 `--mock`을 제외하고 한 번 호출한다. 동일한 문장 출력은 요구하지 않는다. 원격 미실행이면 그 사실을 기록한다.

**예상 출력의 형태:** `langchain ...`, `렌더링 타입: ChatPromptValue`, `응답 타입: AIMessage`, 한 문장 응답. 모델 앞까지는 로컬 작업이고 마지막 모델 invoke에서 원격 요청이 생긴다.

**실패 회복:** import 오류는 `sys.executable`과 설치 경로를 먼저 맞춘다. API 설정 실패는 모의 실행으로 학습을 계속하고 권한 문제를 분리한다. 설치가 지연되면 교사가 렌더링 결과를 보여 주고 dict 대응 활동을 먼저 진행한다. 로컬 환경 설치 통과는 별도 체크한다.

**형성평가 5분:** AI·해설 없이 제공 코드 두 줄 `a=prompt.invoke(data)`, `b=model.invoke(a)`에 대해 각 출력 타입과 원격 호출 위치를 적는다. 코드 열람과 Python REPL은 허용한다. 두 타입과 호출 위치가 모두 맞으면 통과한다.

**예상 오개념 → 보충 → 재평가:** ‘invoke는 모두 유료 요청’ → 모델 없이 템플릿만 실행 → `prompt.invoke({'question':'새 질문'})`의 비용 여부와 타입을 다시 설명한다.

**선택 확장:** API 키를 출력하지 않고, 현재 Python 실행 파일과 패키지 버전이 왜 재현성 증거인지 설명한다.

**다음 회상:** 2교시 시작에 ‘질문만 바꿨을 때 새로 만들어지는 객체는 무엇인가?’를 자료 없이 답한다.

## 2교시 — 변수와 역할을 가진 프롬프트를 만든다

**문제 상황:** 신입사원과 협력사에 같은 공지를 쓰지만 말투와 독자가 다르다. 날짜와 장소는 바뀌어도 사실을 임의로 만들면 안 된다.

### 목표와 성공 증거

| 목표 | 활동 | 제출 증거 | 통과 기준 |
| --- | --- | --- | --- |
| 역할·지시·맥락과 가변 값을 분리한다 | 메시지·변수 대응표 작성 | 템플릿·렌더링 메시지 | 두 역할과 세 필수 변수 정확히 지정 |
| partial로 입력 계약을 줄인다 | tone 사전 지정 | 남은 변수 목록·새 입력 | audience/notice만으로 렌더링, 원본 템플릿은 유지 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | 전 교시의 두 invoke 차이 회상 |
| 5~17분 | README 2장: 템플릿·역할·partial |
| 17~40분 | 렌더링 예측·새 템플릿 작성·partial 실험 |
| 40~45분 | 새 조건 입력으로 자기 검증 |
| 45~50분 | 독립 형성평가 |

### 수행 순서

1. `python -m lessons.s02_prompt.main`을 실행한다. API 키가 없어도 된다.
2. `common/prompts.py`의 `make_prompt()`를 읽고 `{audience}`, `{tone}`, `{notice}`가 어디에 들어가는지 표시한다. 출력 역할의 `.type`은 `system`, `human`으로 관찰한다.
3. 확장 파일 `submission/practice02.py`에서 새 템플릿을 작성한다. system에는 ‘제공 사실만 사용’, human에는 ‘독자/어조/사실’을 둔다. 세 값은 `협력사 담당자`, `격식 있게`, `11월 25일까지 검수자료 제출. 방법은 미정.`이다.
4. 모델 없이 `invoke(...).to_messages()`를 출력한다. 원문에 없는 제출 방법을 이 단계에서 프로그램이 추가했는지 확인한다.
5. `partial(tone='격식 있게')`를 적용하고 남은 변수를 적는다. 원본 템플릿과 새 템플릿의 변수 목록을 각각 확인한다.
6. 새 템플릿에서 `notice`를 빼 보고 어떤 단계에서 실패했는지 적는다. 복구 후 정상 입력으로 다시 렌더링한다.

**새 조건:** 독자는 ‘교육생’, 사실은 ‘준비물은 아직 미정’이다. 별도 모델 호출 없이 같은 템플릿을 재사용한다. 템플릿 문장을 매번 수작업으로 복사하지 않는다.

**확인할 결과:** 필수 변수 세 개, partial 후 두 개. 출력 메시지에는 입력한 독자·어조·사실이 나타난다. 이때 생성된 안내문은 아직 없다.

**실패 회복:** 역할 문자열 오타와 입력 키 오타를 나누어 본다. 변수 목록을 출력한 뒤 dict 키와 표로 대응한다. 공백 값은 렌더링될 수 있다는 것을 확인하고 5교시 검증으로 연결한다.

**형성평가 5분:** AI·해설 없이 `('human','대상: {reader}\n내용: {body}')`의 필수 변수와 정상 입력 dict를 작성한다. 코드·REPL 허용. `partial(reader='교육생')` 이후 남는 변수까지 맞으면 통과한다.

**예상 오개념 → 보충 → 재평가:** ‘partial은 모델 응답을 미리 만든다’ → 모델 없이 partial 전후 변수만 출력 → `partial(body='모집 마감')`을 적용했을 때 남은 변수를 답한다.

**선택 확장:** 변수 값을 모두 채운 템플릿을 만들고 빈 dict로 렌더링해 본다. 이것이 장기 기억인지 설명한다.

**다음 회상:** 3교시 시작에 ‘렌더링된 메시지와 모델 응답은 같은가?’를 답한다.

## 3교시 — LCEL로 문자열 응답을 반환한다

**문제 상황:** 모델 응답 객체 전체를 다른 함수에 넘겼더니 문자열이 필요한 코드가 실패한다. 중간 타입과 최종 타입을 맞춰야 한다.

### 목표와 성공 증거

| 목표 | 활동 | 제출 증거 | 통과 기준 |
| --- | --- | --- | --- |
| 프롬프트·모델·파서를 연결한다 | 단계 실행과 LCEL 비교 | chain 코드·문자열 결과 | 정상 입력에서 str 반환 |
| 중간 타입과 호출 수를 추적한다 | 단계별 출력 관찰 | 타입 표·호출 수 예측 | dict/ChatPromptValue/AIMessage/str 구분, 예제 총 2회 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | 템플릿 입력 계약 회상 |
| 5~17분 | README 3장: Runnable·파이프·파서 |
| 17~40분 | 단계별 실행·LCEL 작성·새 입력 전달 |
| 40~45분 | 출력 타입 검사와 호출 수 점검 |
| 45~50분 | 독립 형성평가 |

### 수행 순서

1. `python -m lessons.s03_lcel.main --mock` 실행 전에 단계별 타입을 적는다.
2. 출력에서 `ChatPromptValue AIMessage str 호환: True`를 확인한다. 코드 안의 모델 호출 두 위치를 찾는다.
3. `submission/practice03.py`에 직접 `prompt`, `model`, `parser`, `chain`을 선언한다. 공통 팩토리는 재사용할 수 있다. 필수 핵심은 `prompt | model | parser`를 스스로 연결하는 것이다.
4. 첫 입력의 독자는 ‘전 직원’, 사실은 ‘금요일 18시까지 합성 보안점검 확인’으로 넣는다. `assert isinstance(answer,str)`로 출력 계약을 확인한다.
5. 같은 체인에 ‘신입사원/교육 일정 미정’ 입력을 넣는다. 키를 새로 만들거나 템플릿을 다시 복사할 필요가 있는지 설명한다.
6. API 사용 시 불필요하게 단계별 실행과 체인 실행을 반복하지 않는다. 원격 비교는 교시 예제 한 번으로 충분하다.

**예상 결과:** 문자열 반환. 모의 응답은 원문을 반영하지 않는다. 실제 응답은 제목·핵심·행동을 따를 수 있지만 이 단계의 타입 검사만으로 준수를 보장하지 않는다.

**실패 회복:** `print(answer.content)`에서 실패했다면 최종 answer가 str인지 먼저 확인한다. 파서 전 응답과 파서 후 응답의 변수명을 나누고 검사한다.

**형성평가 5분:** AI·해설 없이 `prompt | model`과 `prompt | model | StrOutputParser()`의 반환 타입을 설명하고, 후자의 결과를 `.content`로 읽어야 하는지 답한다. 한 줄 수정과 타입 설명이 모두 맞으면 통과한다.

**예상 오개념 → 보충 → 재평가:** ‘파서는 사실을 검증한다’ → 사실과 다른 합성 AIMessage도 문자열로 변환되는지 확인 → 새 합성 메시지를 변환한 뒤 사실 확인 여부를 말한다.

**선택 확장:** 체인 선언 시점과 실행 시점을 나누고 모델 호출 횟수를 종이에 예측한다.

**다음 회상:** 4교시 시작에 ‘출력이 str면 좋은 응답인가?’와 이유를 말한다.

## 4교시 — 동일 조건으로 프롬프트를 비교한다

**문제 상황:** ‘알아서 잘 써 줘’라는 지시 대신 형식과 사실 준수 규칙을 추가하려 한다. 실제로 도움이 되었는지 기록으로 판단해야 한다.

### 목표와 성공 증거

| 목표 | 활동 | 제출 증거 | 통과 기준 |
| --- | --- | --- | --- |
| 동일 입력·모델의 A/B 실험을 실행한다 | 합성 3사례·두 프롬프트 비교 | 6건 JSON 기록 | 사례별 A/B 쌍·공급자/모델·성공/실패가 남음 |
| 기준표로 응답을 평가하고 한계를 설명한다 | 사실·형식·행동 채점 | 비교표·결론 3문장 | 점수 근거를 원문에 연결, 모의 품질 점수 제외 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | 출력 타입과 품질의 차이 회상 |

| 15~35분 | 6회 호출·로그 확인·대기/실패 복구 |
| 35~45분 | 사람 채점·짝과 근거 비교 |

### 수행 순서

## 7교시 — 배치 체인을 직접 구현한다

**문제 상황:** 공지 두 개를 같은 규칙으로 처리해야 한다. 복사한 코드 두 벌 대신 재사용 체인과 입력 목록을 설계한다.

| 호출 수·동시성·공급자 교체 범위를 설명한다 | batch 설정·선택 실행 비평 | 호출량·비교 한계 설명 | 2입력 2회, max_concurrency와 속도 제한 구별 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | assign과 입출력 계약 지연 회상 |

### 필수 요구사항

수정 파일은 `lessons/s07_independent/main.py`다. `build_batch_chain(model)`을 구현한다.

- 입력은 `audience`, `tone`, `notice`가 있는 dict다.
- 공통 검증 함수의 타입·공백·길이 규칙을 사용한다.
- 공통 프롬프트 또는 동일 계약의 자체 프롬프트를 사용한다.
- 전달받은 `model`을 사용한다. 함수 내부에서 키를 읽거나 다른 모델을 몰래 생성하지 않는다.
- 출력은 안내문 `str`이다. 한 입력을 통과시킨 뒤 두 개로 확장한다.
- 시작 코드의 `batch(..., config={'max_concurrency':1})`를 유지한다.

연습 구현에는 AI 오류 해설을 허용하되 대화 요약을 남긴다. 전체 해설 복사는 표시한다. 45~50분 독립 확인은 AI를 사용하지 않는다.

### 수행 순서

1. 코드 작성 전에 네 단계의 입출력 타입을 종이에 적는다.
2. 함수 몸체를 구현하고 `python -m lessons.s07_independent.main --mock`을 실행한다. 두 문자열이 입력 두 개와 순서대로 대응하는지 확인한다.
3. 공백 공지 하나를 별도로 `invoke`해 거절 여부를 확인한다. 오류가 모델까지 넘어가지 않아야 한다.
4. OpenAI 실제 실행을 한 번 수행하면 2회 호출이다. 날짜 미정 사례를 사람 기준으로 확인한다.
5. 여유가 있을 때 `--stream`을 추가한다. 합성 실행과 실제 실행에서 출력 조각의 차이를 관찰한다. 실제 모드에서는 1회 추가 요청이다.
6. Groq 선택 반복 시 `.env`에 해당 공급자 설정을 넣고 `--provider groq`로 실행한다. 실패 시 멈추고 상태를 기록한다. OpenAI로 자동 우회하지 않는다.

**예상 결과:** 기본 실행은 문자열 2개다. 같은 합성 문장이 두 번 나와도 모의 체인 구조가 틀렸다는 뜻은 아니다. 실제 내용 품질은 원문별로 따로 확인한다.

**실패 회복과 힌트:**

1. 질문: ‘모델 앞 입력 타입은 무엇이어야 하는가?’
2. 개념: ‘검증은 dict를 반환하고 프롬프트는 ChatPromptValue를 만든다.’
3. 의사코드: `입력 검사 → 프롬프트 채우기 → 모델 실행 → 문자열 변환`.
4. 부분 코드: `RunnableLambda(validate_input) | ...`.
5. 마지막에만 `solutions/session07.py`를 확인한다. 이후 다른 변수 이름의 템플릿으로 다시 설명한다.

**형성평가 5분:** AI·해설 없이 입력 3개를 batch로 실행하고 stream을 한 번 더 실행할 때 예상 모델 호출 수를 답한다. `max_concurrency=1`이 분당 제한을 자동 해결하는지도 설명한다. 4회와 속도 제한의 차이를 모두 맞히면 통과한다. 제공 코드는 열람 가능하다.

**예상 오개념 → 보충 → 재평가:** ‘batch는 공급자에 한 번만 요청한다’ → 합성 spy로 입력 2개 처리 시 모델 함수 실행 수 관찰 → 입력 4개일 때 호출 수를 예측한다.

**선택 확장:** OpenAI/Groq 결과를 비교하려면 ‘공급자+모델 구성 비교’로 적고, 입력·기준표는 동일하게 유지한다. 선택 때문에 필수 구현 시간이 부족해지면 생략한다.

**다음 회상:** 8교시 시작에 ‘batch 결과와 요청을 연결할 때 필요한 식별값은 무엇인가?’를 답한다.

## 8교시 — 요청 ID가 보존되는 서비스를 설계한다

**문제 상황:** 고객별 요청 두 건의 답변이 섞이면 안 된다. 모델이 안내문을 쓰더라도 요청 ID와 원문은 Python 로직이 정확하게 보존해야 한다.

### 목표와 성공 증거

| 목표 | 활동 | 제출 증거 | 통과 기준 |
| --- | --- | --- | --- |
| 입력 검증·답변 생성·출력 보존을 독립 설계한다 | build_service 작성 | 코드·출력·경계값 기록 | ID/원문 유지, answer str, 모델 최대 1회/정상 요청 |
| 새 조건에 설계를 전이하고 근거를 설명한다 | 변경 요구 분석·시연 | 타입 설명·partial 설계 | ID를 모델에 맡기지 않는 이유와 남은 변수를 설명 |

### 50분 진행

| 시간 | 활동 |
| --- | --- |
| 0~5분 | 요청 식별값·입출력 타입 회상 |
| 5~10분 | 계약과 제출 기준 확인 |
| 10~35분 | 독립 설계·구현·로컬 점검 |
| 35~45분 | 시연·질문·피드백 및 새 조건 수정 |
| 45~50분 | 최종 형성평가·다음 항목 회상 예약 |

### 종합 요구사항

수정 파일은 `lessons/s08_capstone/main.py`, 구현 함수는 `build_service(model)`이다. 25분 독립 수행 동안 AI 코딩 도구·solutions는 금지한다. README, 공통 함수, 빈 테스트 양식, Python REPL은 허용한다. 이전에 작성한 7교시 코드는 참조할 수 있다. 해설을 보았다면 제공 입력을 바꾼 새 수행으로 재평가한다.

| 항목 | 계약 |
| --- | --- |
| 입력 키 | request_id, audience, tone, notice |
| request_id | 비어 있지 않은 str, 원래 길이 80자 이하, 양끝 공백 제거 |
| 공지 입력 | common.prompts.validate_input 규칙 적용 |
| 정상 출력 | 정확히 request_id, notice, answer 세 키 |
| 값 보존 | request_id와 notice는 정리된 입력과 동일 |
| answer | 모델과 문자열 파서를 거친 비어 있지 않은 str |
| 오류 입력 | 빈 ID·정수 ID·공백 공지는 모델 호출 전에 거절 |
| 원격 요청 | 정상 입력당 1회, 실패 입력은 0회 |
| 내용 기준 | 원문에 없는 날짜·장소·제출처를 임의 단정하지 않음 |

정상 출력의 구조는 Python이 만들고 안내문 문장은 모델이 만든다. 두 책임을 혼동하지 않는다.

### 시험 입력

```python
normal = {
    'request_id': 'NEW09',
    'audience': '신규 협력사',
    'tone': '격식 있게',
    'notice': '자료 제출 기한은 미정입니다. 담당자에게 확인하세요.',
}
# 경계값은 normal에서 한 값만 바꿔 각각 실행한다.
# request_id='' / request_id=123 / notice='  '
```

**새 전이 입력:** `request_id='NEW10'`, 독자 ‘교육생’, 사실 ‘교육 장소는 미정. 일정은 금요일에 공지.’로 한 번 더 검증한다. 코드에 `NEW09`나 예시 공지를 하드코딩하지 않는다.

### 수행 순서

1. 함수 연결 전에 `dict → 정리된 dict → answer 추가 dict → 세 키 dict`의 흐름을 적는다.
2. request_id 검증과 공지 검증을 합친다. 기존 검증 함수가 ID를 반환하지 않는다는 점에 주의한다.
3. 입력을 보존하면서 답변을 추가한다. 모델에게 요청 ID를 다시 쓰도록 지시하지 않는다.
4. 필요한 출력 키만 선택한다. 정상 요청에서 임의의 모델 호출을 한 번 더 넣지 않는다.
5. `python -m lessons.s08_capstone.main --mock`과 `python -m tests.check_submission`을 실행한다.
6. 실제 API가 있으면 정상 입력 한 건을 실제 실행하고 사람이 내용 기준을 확인한다. 키가 없으면 구조 검증과 내용 품질 미실행을 구분한다.
7. 35~45분 시연에서 정상·오류 입력 각 한 개를 보여 주고, 모델 호출 전후에 남는 키를 설명한다.

**실패 회복:** ID가 사라지면 입력 검증 함수의 반환값을 본다. ID는 남고 notice가 새 문장으로 바뀌었다면 모델 응답과 원문을 혼합했는지 본다. 완성 해설은 독립 수행 시간 이후 `solutions/session08.py`로 확인한다.

### 종합평가 루브릭

| 영역 | 배점 | 충분한 수행 | 부분 수행 | 미충족 |
| --- | ---: | --- | --- | --- |
| 기능 | 35 | ID/원문 보존·세 키·문자열·실제 1회 구조 모두 충족 | 일부 출력·보존 조건 누락 | 정상 경로 미완성 |
| 설계 판단 | 25 | 검증 위치·모델 책임·데이터 보존 이유 설명 | 코드 동작 설명 일부 가능 | ID를 모델에 맡기거나 흐름 설명 불가 |
| 검증 | 25 | 정상+새 입력+세 오류·호출 전 거절 증거 | 정상과 일부 오류만 확인 | 화면 한 장만 제출 |
| 설명·전이 | 15 | 단계 타입·호출 수·partial 변경을 독립 설명 | 원래 사례만 설명 | 해설을 읽는 수준 |

충분한 수행은 해당 배점 전부, 부분 수행은 절반(소수점 유지), 미충족은 0점으로 채점한다. 설계상 통과선은 70점이며 **정상 출력 계약과 잘못된 입력의 모델 전 거절은 필수**다. 실제 API 미실행으로 모델 문장 품질을 확인할 수 없으면 로컬 역량 결과와 생성 품질 ‘미실행’을 함께 기록한다. 키를 제출물에 포함하면 제거 후 다시 제출한다.

**형성평가 5분:** AI·해설 없이 ‘어조를 격식 있게 고정하고 나머지만 받도록 변경’ 요구에 대해 partial 위치와 남는 필수 변수를 설명한다. 서비스가 받는 request_id와 프롬프트 변수를 나누고, notice/audience가 필요하다는 설명이 맞으면 통과한다.

**예상 오개념 → 보충 → 재평가:** ‘모델에게 ID를 출력시키면 보존 보장’ → 합성 모델이 다른 ID를 말하는 예를 주고 Python 보존 값과 비교 → 다른 요청 ID에서도 같은 출력 계약을 설계한다.

**다음 항목의 지연 회상:** 문제 분해 프롬프트를 배울 때 오늘의 입력 dict와 LCEL을 그대로 재사용하고, 프롬프트만 바꾼 비교를 설계한다. 내부 사고 노출 대신 간결한 풀이·검증 요약을 대상으로 한다.
