## 설계 요약

- **MVP 범위:** 서울 광화문 고정, 가상 숙소·날씨와 Google Maps 경로/장소를 이용한 읽기 전용 추천.
- **예산/정렬:** 150,000 KRW/실/박은 조정 가능한 제안 기본값이다. hard constraint 적용 후 숙박 총액이 낮은 순서로 추천한다.
- **실시간성:** 장기 목표는 실시간 데이터다. 최초 MVP는 숙소/날씨를 가상 데이터로 표시하고 Google Maps는 provider adapter로 연결한다.
- **LLM 역할:** 누락된 조건 확인, 도구 선택과 호출, 여러 출처의 근거를 사용자 답변으로 정리.
- **도구 역할:** 필터링·조회·경로 계산 등 사실 확인이 필요한 작업을 수행하고 출처와 조회 시각을 반환.
- **CoT 원칙:** 모델의 비공개 사고 과정을 출력하거나 저장하지 않는다. 의도, 제약, 선택 근거만 구조화해 추적한다.
- **ReAct 원칙:** 허용 목록에 등록한 읽기 전용 도구만 호출하고, 검증된 도구 결과를 관찰값으로 다음 단계에 전달한다.
- **안전 범위:** 예약·결제·개인정보 저장은 MVP에서 제외한다. Provider interface를 통해 가상 숙소/날씨를 향후 실데이터 adapter로 교체할 수 있게 한다.

구현 단계에서는 사용할 LangChain 버전과 모델 공급자를 고정하고, 해당 버전의 Agent API에 맞춰 어댑터를 구현한다. 현재 교육 프로젝트의 의존성만으로는 LangChain ReAct Agent와 공급자 연결을 바로 실행할 수 있다고 가정하지 않는다.

## 1차 구현

현재 구현은 규칙 기반 의도 추출, 광화문 가상 숙소/날씨, Google Maps mock 장소·경로, 예산순 정렬을 연결한 결정론적 세로 기능이다. 외부 API나 모델을 호출하지 않으며, 실 Google Maps adapter와 LangChain ReAct는 다음 개발 단계로 남겨 둔다.

프로젝트 폴더에서 다음처럼 실행한다.

```powershell
py -m travel_mvp "내일 광화문 2명 1박, 숙소 15만원 이하, 비 예보를 고려해줘"
```

날짜가 질문에 없으면 확인 질문을 반환한다. 인원(2명), 숙박(1박), 예산(150,000원/실/박)은 초기 제안 기본값이며 실제 응답의 `assumptions`에 표시한다.
질문에 예산이 없을 때 기본 예산을 바꾸려면 `--default-budget-per-night 100000`처럼 지정한다.
