업무에서 출발하기

쇼핑몰 상담원은 같은 반품 정책을 여러 고객에게 반복해서 설명한다. 매번 직접 작성하면 시간이 걸리고, 회사 정책과 다른 안내가 섞일 수 있다. 오늘 만들 프로그램은 고객 문의와 회사 정책을 받아 상담원이 검토할 답변 초안을 만드는 도우미다. 반품을 승인하거나 실제 메시지를 발송하지 않는다. 프로그램의 입력은 문의 텍스트, 근거는 운영자가 관리하는 정책 파일, 출력은 검토용 답변 문자열이다.

이 프로그램에서 자연어를 생성하는 주체는 LLM이다. LangChain은 문의를 적절한 메시지로 만들고, 모델을 호출하고, 받은 결과를 다음 처리로 넘기는 연결 구조를 제공한다. 프레임워크를 설치했다고 모델이 PC 안에 다운로드되지는 않는다. OpenAI를 선택하면 네트워크를 통해 해당 서비스의 모델을 호출한다. 모의 모드는 호출 없이 고정된 응답을 돌려준다.

모델·API·프레임워크를 나누어 생각하기

식당에 비유하면 모델은 조리 능력, API는 주문을 주고받는 창구, LangChain은 주문서를 정리하고 결과를 전달하는 작업 흐름이다. 실제로는 API 키가 호출 권한을 제공하고 모델 ID가 호출 대상을 정한다. 둘 중 하나만 맞아서는 실행되지 않는다. 비유의 ‘조리 능력’과 달리 모델은 회사의 현재 주문 상태를 스스로 조회하지 못한다. 조회 시스템과 연결하지 않은 정보는 프로그램이 알 수 없다.

LangChain은 모듈로 나뉜 생태계다. 이번 범위는 템플릿·LCEL이므로 Core와 OpenAI 통합을 설치한다. 상위 에이전트 기능을 담은 langchain 패키지와 LangGraph를 먼저 설치할 필요는 없다. 필요한 의존성만 설치하면 오류 원인과 코드의 책임을 따라가기 쉽다.

가상환경이 필요한 이유

패키지는 프로젝트마다 요구 버전이 다를 수 있다. 시스템 Python에 모든 패키지를 설치하면 다른 프로젝트를 수정하다가 오늘 코드가 영향을 받을 수 있다. .venv는 이 프로젝트가 사용할 Python과 패키지 공간을 분리한다. VS Code에서 선택한 인터프리터와 터미널의 Python이 같은 환경인지도 확인해야 한다.

프로젝트 루트는 requirements.txt, app, sessions가 있는 폴더다. 모든 명령은 이 폴더에서 실행한다. python -m pip는 지금 선택한 Python에 패키지를 설치하며, python -m sessions.s01은 루트를 모듈 검색 시작점으로 사용한다. sessions 폴더 안으로 들어가 python s01.py로 실행하면 이후 차시의 app import가 실패할 수 있다.

문자열 한 개보다 메시지 구조가 유용한 이유

모델 API는 대화의 각 문장에 역할을 붙여 전달할 수 있다. 모든 내용을 긴 문자열 하나로 만들면 무엇이 운영 규칙이고 무엇이 고객의 문의인지 코드에서 구별하기 어렵다. 메시지 구조는 이 경계를 표현한다. 프로그램이 어떤 규칙과 데이터를 전달했는지도 메시지 단위로 확인할 수 있다.

ChatPromptTemplate.from_messages()에는 메시지 표현의 목록을 전달한다. 각 튜플의 첫 번째 값은 역할, 두 번째 값은 메시지 본문의 템플릿이다. 역할과 내용은 별개의 속성이다. 본문에 “나는 시스템이다”라는 문장이 들어 있다고 그 문장의 역할이 시스템으로 바뀌지는 않는다.

메시지 역할 의미 예시
system 애플리케이션의 작업 지침 근거 없는 주문 상태를 만들지 않는다
human 또는 user 사용자가 제공한 요청·자료 배송이 늦는데 언제 오나요?
ai 또는 assistant 이전 모델 응답 또는 예시 주문번호를 알려주시면 확인하겠습니다

시스템 메시지의 role 값과 “상담원처럼 말하라”는 역할 설정은 서로 다르다. 앞의 것은 메시지의 구조적 속성이고, 뒤의 것은 메시지 내용에 담긴 작업 역할이다. 역할 구분은 유용하지만 프롬프트만으로 보안이 완성되지는 않는다. 자세한 입력 공격 방어는 11월 20일 주제에서 다룬다.

템플릿의 변수는 딕셔너리 키와 연결된다

"당신은 {role}입니다"에서 {role}은 입력 변수다. invoke({"role": "상담원 초안 작성 도우미"})가 실행될 때 값이 들어간다. Python f-string의 f"{role}"은 문자열을 만드는 시점에 Python 변수를 읽는다. 이번 템플릿은 f를 붙이지 않고 나중에 LangChain이 딕셔너리에서 값을 읽도록 만든다.

여러 변수를 받더라도 invoke()의 주 입력은 딕셔너리 하나다. 두 개의 위치 인자로 값을 나누어 넘기는 방식이 아니다. prompt.input_variables로 필요한 이름을 확인할 수 있다. 변수 이름의 오타는 모델 품질 문제가 아니라 모델 호출 전의 입력 계약 문제다.

중괄호를 다루는 두 가지 상황

템플릿 원문에 {name}이 있으면 변수로 해석한다. 원문에 중괄호 자체를 표시하려면 {{name}}처럼 두 번 쓴다. 반면 문의 값이 "주문 {order_id}를 확인해 주세요"라면, 이 값 안의 중괄호는 다시 템플릿 변수로 해석되지 않는다. 삽입될 데이터와 템플릿 원문을 혼동하지 않는 것이 중요하다.

LCEL은 실행 순서를 표현한다

프롬프트를 만든 뒤 모델에 보내고 응답에서 텍스트를 얻는 작업은 일반 Python 변수로도 작성할 수 있다. LCEL은 이 연결 관계를 Runnable이라는 공통 인터페이스로 표현한다. invoke()는 하나의 입력을 처리한다. 연결된 부품의 앞 출력이 뒤 부품의 입력이 된다.

value = prompt.invoke(inputs)
message = model.invoke(value)
text = output_parser.invoke(message)

위 순서를 선언적으로 쓰면 chain = prompt | model | output_parser다. 여기서 |는 비트 OR 계산이나 터미널의 파이프 명령을 그대로 실행하는 것이 아니다. Runnable이 연산자를 재정의해 순차 실행 객체를 만든다. chain을 구성하는 줄에서는 API 요청이 발생하지 않고 chain.invoke(inputs)를 실행할 때 모델 호출이 일어난다.

자료형이 연결되어야 흐름이 이어진다

컴포넌트 입력 출력 하는 일
ChatPromptTemplate 템플릿 변수 딕셔너리 ChatPromptValue 역할 있는 메시지 구성
채팅 모델 프롬프트/메시지 AIMessage 모델 응답 수신
StrOutputParser 모델 메시지 str 텍스트를 꺼내 다음 처리에 전달

AIMessage에는 응답 본문 외에도 모델별 메타데이터와 사용량이 포함될 수 있다. 화면에 문장만 보여줄 때는 파서가 편리하다. 사용량을 기록하려면 파서 이전 단계에서 메시지를 받아야 한다. 7차시 비교 프로그램이 이 이유로 prompt | model 결과를 먼저 기록한다.

최신 라이브러리에서는 파서의 반환 클래스 이름이 TextAccessor로 보일 수 있다. 이는 문자열 하위형이며 표의 str은 문자열 계열 계약을 뜻한다. 클래스 이름과 값의 사용 계약을 구분한다.

파서는 문법이나 정책을 검증하는 만능 검사기가 아니다. StrOutputParser에 “환불이 완료되었습니다”라는 메시지를 넣으면 그대로 텍스트를 돌려준다. 실제 환불 여부나 사실 정확성을 보장하지 않는다. 이번 프로젝트가 결과에 ‘초안’이라고 표시하는 이유다.

공통 맥락을 고정하는 partial

정책은 고객마다 바뀌지 않으므로 prompt.partial(context=load_policy())로 미리 채울 수 있다. 그러면 호출 시에는 inquiry만 넘긴다. partial은 모델 학습이나 응답 캐시가 아니다. 템플릿의 일부 변수 값을 고정한 새로운 프롬프트를 만드는 작업이다. 정책 파일을 바꾸더라도 이미 만들어진 프롬프트에는 이전 값이 남으므로 다시 생성해야 한다.

    provider: str
    model: str

        if provider not in {"openai", "groq", "mock"}:
            raise ValueError("LLM_PROVIDER는 openai/groq/mock 중 하나여야 합니다.")
        prefix = provider.upper()

        if not model:

        temperature = float(raw) if raw else None
        if temperature is not None and not 0 <= temperature <= 2:
            raise ValueError("LLM_TEMPERATURE는 0~2 범위여야 합니다.")
        return cls(provider, model, temperature=temperature)

프롬프트가 모든 일을 처리하게 하지 않는다

빈 문의가 들어왔을 때 모델에게 “문의가 비었는지 판단해 줘”라고 요청할 필요는 없다. Python이 정확하고 저렴하게 처리할 수 있는 일이다. 문자열 여부, 공백 입력, 길이 제한 같은 조건은 모델 호출 전에 검사한다. 모델은 규칙으로 처리하기 어려운 자연어 생성에 사용한다.

전처리는 데이터를 원하는 계약에 맞게 만드는 과정이다. 이번에는 앞뒤 공백을 제거하고 문의의 길이를 검사한다. 문장 내부의 숫자, 부정 표현, 주문번호, 중괄호를 삭제하지 않는다. 특히 “미사용”을 “사용”으로 바꾸거나 두 문장을 임의로 합치면 업무 의미가 달라질 수 있다.

입력 처리 결과 모델 호출
{"inquiry": " 반품 문의 "} 공백 제거 후 문의 전달 진행
{"inquiry": ""} 값 오류 없음
{"inquiry": None} 값 오류 없음
{"inquiry": "가" * 1001} 수업용 길이 제한 오류 없음
"반품 문의" dict 형식 오류 없음

1000자는 수업에서 정한 문자 수 제한이며 1000토큰 제한이 아니다. 한국어 토큰 수는 문자 수와 일치하지 않는다. 큰 문서의 토큰 예산은 별도 측정해야 한다.

RunnableLambda는 Python 함수를 체인 부품으로 만든다

normalize_request(row)는 딕셔너리를 받아 {"inquiry": 정리한_문자열}을 반환한다. RunnableLambda(normalize_request)로 감싸면 다른 Runnable처럼 invoke, batch에 연결할 수 있다. 함수에 여러 업무 값이 필요하면 여러 위치 인자를 임의로 늘리는 대신 딕셔너리 하나로 전달하면 연결 계약이 단순해진다. 추가 설정 인자를 받는 고급 형태도 있지만 오늘은 단일 업무 입력에 집중한다.

chain = (
    RunnableLambda(normalize_request)
    | prompt
    | model
    | StrOutputParser()
)

normalize_request에서 예외가 발생하면 뒤의 prompt·model로 넘어가지 않는다. 이런 구조가 입력 오류에 불필요한 호출 비용이 발생하는 것을 막는다. 단, 실제 서비스의 보안 요구를 문자열 검증만으로 해결하는 것은 아니다.

정책과 고객 입력을 분리한다

CSV에 고객이 context라는 칼럼을 추가했다고 회사 정책이 바뀌면 안 된다. normalize_request는 문의만 반환하고, 정책은 build_chain()이 운영자 파일에서 읽어 고정한다. 필요한 데이터만 다음 단계에 넘기는 설계다. 이는 ‘유효한 dict인가’뿐 아니라 ‘누가 어떤 값을 정할 수 있는가’를 구분하는 문제다.

책임도 나눈다. app/config.py는 설정, app/providers.py는 공급자 연동, app/prompts.py는 메시지, app/pipeline.py는 입력과 흐름을 담당한다. 처음부터 모든 클래스를 만들 필요는 없지만, 실습이 커질수록 각 변경의 위치를 알 수 있어야 한다.

import csv
import json
from pathlib import Path
from langchain_core.runnables import RunnableLambda
from langchain_core.output_parsers import StrOutputParser
from app.config import ROOT
from app.prompts import get_prompt


def load_policy():
    return (ROOT / "data/policy.txt").read_text(encoding="utf-8").strip()


def normalize_request(row):
    if not isinstance(row, dict):
        raise TypeError("입력은 dict여야 합니다.")
    value = row.get("inquiry")
    if not isinstance(value, str) or not value.strip():
        raise ValueError("inquiry는 공백이 아닌 문자열이어야 합니다.")
    value = value.strip()
    if len(value) > 1000:
        raise ValueError("inquiry는 1000자 이내여야 합니다.")
    # 원문의 의미·숫자·중괄호는 바꾸지 않는다.
    return {"inquiry": value}


def build_chain(model, version="designed"):
    # 운영자가 관리하는 정책은 시작 시 고정한다. 고객 CSV에서 context를 받지 않는다.
    prompt = get_prompt(version).partial(context=load_policy())
    return RunnableLambda(normalize_request) | prompt | model | StrOutputParser()


def load_cases():
    return json.loads((ROOT / "data/cases.json").read_text(encoding="utf-8"))


def read_requests(path):
    path = Path(path)
    with path.open(encoding="utf-8-sig", newline="") as f:
        reader = csv.DictReader(f)
        if not reader.fieldnames or not {"id", "inquiry"} <= set(reader.fieldnames):
            raise ValueError("CSV 헤더에는 id,inquiry가 필요합니다.")
        rows = list(reader)
    if len(rows) > 100:
        raise ValueError("수업용 CSV는 최대 100행입니다.")
    ids = [r["id"].strip() for r in rows]
    if any(not x for x in ids) or len(ids) != len(set(ids)):
        raise ValueError("id는 공백 없이 고유해야 합니다.")
    return [dict(r, id=r["id"].strip()) for r in rows]


def write_jsonl(path, rows):
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    # 한국어를 그대로 저장한다. 같은 경로 재실행 시 덮어쓴다.
    with path.open("w", encoding="utf-8") as f:
        for row in rows:
            f.write(json.dumps(row, ensure_ascii=False) + "\n")

batch dict 목록 입력 순서에 대응하는 결과 목록 입력 수만큼
stream dict 하나 문자열 조각 반복자 보통 1회

LCEL의 batch는 공급자의 할인형 비동기 Batch API와 다르다. 목록을 넘겼다고 요청이 하나로 합쳐지는 것은 아니다. 기본 구현은 여러 요청을 병렬 처리할 수 있어 강의실 전체가 동시에 실행하면 계정 한도에 도달하기 쉽다. 실습 코드는 max_concurrency=1로 제한해 3건을 한 번에 하나씩 처리한다. 이는 조직의 모든 학생을 합산한 전역 제한은 아니다.

결과와 예외를 항목별로 다루기

return_exceptions=True를 사용하면 항목의 오류가 결과 목록의 예외 객체로 반환될 수 있다. 입력 목록 순서와 결과 목록 순서를 맞춰 어느 문의가 실패했는지 확인할 수 있다. 이 방식은 실패 항목을 알아보기 쉽지만 이미 시작된 다른 요청을 취소하는 전역 회로 차단기는 아니다. 한도 오류가 발생하면 추가 명령 실행을 멈추고 상태를 확인한다. 8차시 통합 코드는 한도 오류를 만났을 때 다음 행 호출을 중단하도록 별도 순차 루프를 둔다.

import hashlib
import time
from datetime import datetime, timezone
from langchain_core.output_parsers import StrOutputParser
from app.prompts import get_prompt
from app.pipeline import load_policy
from app.providers import friendly_error


def fingerprint(value):
    return hashlib.sha256(value.encode("utf-8")).hexdigest()[:12]


def observations(text):
    # 단순 관측값이다. 사실성·정책 준수·인사 유무의 의미 판정이 아니다.
    return {"characters": len(text), "within_500_chars": len(text) <= 500,
            "mentions_7_days_literal": "7일" in text,
            "nonempty": bool(text.strip())}


def compare_versions(model, settings, cases, repeats=1):
    if type(repeats) is not int or not 1 <= repeats <= 3:
        raise ValueError("repeats는 1~3이어야 합니다.")
    records = []
    context = load_policy()
    for repeat in range(repeats):
        # 순서 영향을 줄이기 위해 반복마다 버전 순서를 순환한다.
        versions = ["weak", "role", "designed"]
        versions = versions[repeat:] + versions[:repeat]
        for case in cases:
            for version in versions:
                prompt = get_prompt(version)
                inputs = {"context": context, "inquiry": case["inquiry"]}
                rendered = prompt.invoke(inputs)
                started = time.perf_counter()
                record = {"case_id": case["id"], "version": version,
                          "repeat": repeat + 1, "provider": settings.provider,
                          "model": settings.model, "temperature": settings.temperature,
                          "max_output": settings.max_output,
                          "checked_at": datetime.now(timezone.utc).isoformat(),
                          "context_hash": fingerprint(context),
                          "inquiry_hash": fingerprint(case["inquiry"]),
                          "prompt_hash": fingerprint(rendered.to_string()),
                          "mode": "mocked" if settings.provider == "mock" else "remote"}
                try:
                    # AIMessage를 받는 지점에서 사용량을 기록한 뒤 텍스트를 추출한다.
                    message = (prompt | model).invoke(inputs)
                    text = StrOutputParser().invoke(message)
                    record.update(status="ok", output=text,
                                  usage=message.usage_metadata,
                                  observations=observations(text))
                except Exception as error:
                    record.update(status="error", error=friendly_error(error))
                record["elapsed_seconds"] = round(time.perf_counter() - started, 4)
                records.append(record)
                if record.get("error", "").startswith("호출/토큰/크레딧"):
                    return records  # 429에서 추가 호출을 중단한다.
    return records

Windows Excel이 만든 CSV에는 BOM이 있을 수 있어 utf-8-sig로 읽는다. csv.DictReader는 헤더를 키로 사용한다. 쉼표가 포함된 문의는 CSV 규칙에 따라 큰따옴표로 감싸야 한다. 직접 split(",")하면 문의 안의 쉼표 때문에 칼럼이 깨질 수 있다.

id가 비거나 중복되면 어느 고객의 결과인지 혼동할 수 있으므로 파일 계약 오류로 중단한다. 문의가 빈 행은 해당 항목만 오류로 기록한다. ‘파일 전체를 읽을 수 없는 오류’와 ‘한 항목이 잘못된 오류’를 다른 수준에서 처리하는 것이다.

하나의 실패가 다른 정상 행을 가리지 않게 한다

통합 프로그램은 한 행씩 체인을 호출하고 성공 결과와 오류를 따로 모은다. 빈 문의는 Python 검증에서 멈추므로 모델 호출이 없다. 일시적 연결 실패도 행 오류로 기록한다. 429는 계정 전체 한도일 수 있어 다음 행 호출을 중단한다. 이때 선택한 행 수와 성공+오류 수가 다를 수 있다. 남은 행은 처리되지 않았으므로 429 원인을 해결한 뒤 필요한 대상만 다시 실행한다.

한 번 더 실행하면 새 시간 이름의 폴더를 만들어 이전 초안을 덮어쓰지 않는다. 다만 실고객 서비스를 만들 때는 중복 실행·발송 방지, 원자적 저장, 인증, 접근 통제, 요청 제한을 추가해야 한다. 오늘은 자동 발송 자체가 없으므로 결과를 검토하는 단계에서 끝난다.

실습 순서

먼저 data/requests.csv의 3개 합성 문의를 살펴본다. 이어 read_requests()로 행을 읽고 id 계약을 확인한다. 모델과 체인은 반복문 밖에서 한 번 구성한다. 각 행에는 inquiry만 전달한다. 마지막으로 정상·오류 결과를 서로 다른 JSONL 파일에 저장한다.

실습 코드는 완성된 모듈을 숨겨 두고 사용하는 구조가 아니다. 앞 차시에서 작성한 설정·프롬프트·전처리 함수를 그대로 재사용한다. 각 차시 본문 뒤에 해당 구현을 함께 제공하므로 파일을 열어 전체 흐름을 따라갈 수 있다.

import argparse
from datetime import datetime
from app.config import ROOT, Settings
from app.providers import make_model, friendly_error
from app.pipeline import build_chain, read_requests, write_jsonl


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--mock", action="store_true")
    parser.add_argument("--input", type=str, default=str(ROOT / "data/requests.csv"))
    parser.add_argument("--limit", type=int, default=3, choices=range(1, 6))
    args = parser.parse_args()
    requests = read_requests(args.input)[:args.limit]
    settings = Settings.read(args.mock)
    chain = build_chain(make_model(settings))
    results, errors = [], []
    for row in requests:
        try:
            draft = chain.invoke({"inquiry": row["inquiry"]})
            results.append({"id": row["id"], "draft": draft, "provider": settings.provider,
                            "model": settings.model, "mode": "mocked" if args.mock or settings.provider == "mock" else "remote"})
        except Exception as error:
            errors.append({"id": row["id"], "error": friendly_error(error)})
            if getattr(error, "status_code", None) == 429:
                break  # 공급자 한도에서는 이후 항목도 호출하지 않는다.
    run = datetime.now().strftime("%Y%m%d_%H%M%S_%f")
    folder = ROOT / "outputs" / f"run_{run}"
    write_jsonl(folder / "drafts.jsonl", results)
    write_jsonl(folder / "errors.jsonl", errors)
    print(f"성공 {len(results)} / 오류 {len(errors)} / 선택 {len(requests)}")
    print("결과:", folder)
    print("초안을 검토한 뒤 사용하세요.")

if __name__ == "__main__":
    try:
        main()
    except Exception as error:
        raise SystemExit(friendly_error(error))
